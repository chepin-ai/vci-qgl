# LABJUDGE-EXT09 三草案判定

## 案① CIRC重做立项（主线B见证证书化内嵌A，C仅探针，AC1–AC5）

**路线稳健性：尚可，但主从关系需要写死。**
"主线B见证证书化内嵌A、C仅探针"这个结构本身是合理的——把重做工期压在最可复现的路径上，避免C路径过早扩张成并行主线。风险点在于"内嵌A"的语义：若A是作为B证书的**证据载荷**（A只读、只被引用）则稳；若A可以反向修改B的见证结构，则等于把A偷偷升级为主线，B的"证书化"就空心化了。

**AC1–AC5可机器复核性：取决于拟成文程度。**
当前描述只有编号，没有可判定谓词。要机器复核，至少需满足：每条AC能映射为一个**可执行断言**（输入固定、输出布尔、失败可定位）。若AC里出现"充分""合理""大致一致"这类量词，则不可复核。建议在立项文本里强制"AC=可执行判据+反例样本"。

**制度漏洞：**
- 缺少**C的探针失败回退条款**——探针污染主线或被主线当作证据引用时的隔离规则未定。
- 缺少**B证书版本与A快照的绑定哈希**，否则"内嵌"会退化成弱引用。

**倾向：可 pass，附条件**（B对A为主、A不可反向改写B；AC全部谓词化；C探针隔离）。

## 案② 缓存锚域限条款（fallthrough DONE四条件 + BLOCKED四触发 + 缓存锚≠内容认证）

**路线稳健性：结构性正确，边界最危险。**
把"缓存锚"与"内容认证"分离是对的——缓存锚只证明**某个已缓存对象的同一性/定位**，不证明**内容真实性**。这条若不写清，下游会把命中缓存当成内容已认证，属典型制度性事故。

**DONE四条件 vs BLOCKED四触发的边界问题：**
- 必须明确两者是**互斥完备**还是**可并存**。若可并存，则DONE会在BLOCKED触发时被误报，需要优先级规则（一般应定为：**BLOCKED优先于DONE**，即任一BLOCKED触发即压制DONE）。
- 四条件/四触发各自需要**判定顺序**。无序判定会导致同一输入在不同执行顺序下得出不同状态，不可机器复核。
- 需要**否定性判据**：DONE四条件全部为真的**同时**要断言四触发全部为假，否则DONE不足以签发。

**"缓存锚≠内容认证"的可复核性：**
这条本身是**元规则**，不能直接作为AC，必须落成具体检查项，例如：签发DONE时禁止把"缓存命中"字段作为内容真实性证据链的一环；若证书里出现该引用，判定为**不合规签发**。

**制度漏洞：**
- 缺**fallthrough到DONE的时序**约束（先缓存后认证 vs 先认证后缓存，会得出不同结论）。
- 缺**BLOCKED解除条件**——四触发是"瞬时"还是"持续"，未定则BLOCKED永挂。
- 缺**审计追溯**：每次DONE/BLOCKED判定需记录触发了哪条、依据哪个锚，否则不可复核。

**倾向：undecided → 需补边界规则后才可 pass。** 若必须二选一，我对"当前文本直接pass"投**反对票**：DONE/BLOCKED优先级与顺序未定，机器复核会出歧义。

## 案③ A1堆叠升级（L0确权锁边界，L1/L2契约JSON化，DISPUTED停层）

**路线稳健性：分层方向对，停让规则是薄弱点。**
L0锁边界、L1/L2契约JSON化是标准做法，可机器校验（JSON schema + L0不可越界断言）。问题在**DISPUTED停层**：

- **停层粒度**未定：是停L1、停L2，还是停整条A1链？若停整链，则L0确权被牵连；若只停L1，L2是否可继续读？需明说。
- **停让规则**要给出**升级/降级路径**：DISPUTED进入后，谁能解除、依据什么、超时怎么办。否则DISPUTED会变成"死锁态"。
- **层级停让**与**L0锁边界**的交互未定：L0已锁的边界在DISPUTED期间是否可被动用？若可，则"锁"名不副实。

**可机器复核性：**
- L1/L2契约JSON化 → 可复核（schema验证）。
- L0确权锁边界 → 可复核（边界断言）。
- DISPUTED停层 → **当前不可复核**，因为缺状态迁移表。

**制度漏洞：**
- 无**DISPUTED超时/仲裁**条款 → 死锁风险。
- 无**跨层证据不可上推**规则 → L2的争议可能被误升到L0。
- 无**解除DISPUTED后的重入校验** → 解除即恢复，可能绕过原争议。

**倾向：可 pass，附条件**（补状态迁移表+超时仲裁+跨层证据规则）。
